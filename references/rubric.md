# 判据手册：什么算「不均匀空白」

来源：Alonzo《提升顶会投稿美感的六大焚决——消除「不均匀空白」》。原则一句话：**把 PDF 缩到 50%，退后半步，每栏都应该是一个边缘锋利、深浅一致的矩形。**

下面每条都给了：判据、阈值、为什么是这个问题、以及**什么情况下不算**（这是最容易出错的部分）。

---

## 1. 寡行（widow / orphan / runt）

**判据**：段落最后一行太短，在矩形右下角抠掉一块。

| 级别 | 末行占栏宽 | 判定 |
|---|---|---|
| 不可接受 | < 50% | 必须处理（多数课题组的硬要求） |
| 不够好 | 50–70% | 建议处理 |
| 合格 | ≥ 70% | 放过 |

**变式（更严重）**：段落最后**一句**整句掉到下一栏或下一页，或者段末一行孤零零挂在栏首（lonely widow）。这类断段让读者在翻栏时读到半句话，是「结构性的不均匀空白」。

**为什么**：reviewer 的余光不看字，只看形状。右下角缺一块 ＝ 这个作者连版面都没检查。反过来，故意让每段末行都短，是本科凑页数的老 trick——会被读成「肚子里没货」。

**不算的情况**：
- 末行承载的是独立语义单元（一条结论、一个公式编号、一句 `\caption` 的收尾），压上去会牺牲可读性；
- 同一段末行 < 50% 但**同一栏内**还有图表占据下方的空白，矩形并未被破坏（脚本会把它算作末行，需要你目视复核）；
- 单栏摘要、`\begin{center}` 内的短行、条目列表（bullet）的末项。

**处理优先级**：先删冗余词/换短表述压回上一行（不改变信息量），再考虑加半句让末行变长；`\looseness=-1`、`\enlargethispage` 是版式兜底手段，会牵动其它段落，最后用。

## 2. 结果图（results figure）

**判据**（四条，按重要性排序）：

1. **legend 不压数据**：图例遮挡曲线/散点 ＝ 读者要猜。宁可把图例放图外一行，也不要半透明压在数据上。
2. **子图刻度对齐**：并排子图刻度条数不同（左图 5 个、右图 3 个），会造成两图视觉高度不同、与页上沿的边距不一致。统一刻度区间，找一个两边都合适的 granularity。
3. **填满栏宽**：图宽 = 可用栏宽（或版心宽）；两侧各留 20–30% 白是最常见的"业余感"来源。
4. **等比缩放**：只改宽度不改高度，图会变形。要更宽就改画布比例，不要拉伸。

**构图习惯**：把结果图做成「长条矩形」（宽明显大于高），比接近正方形或竖长的图更容易与文字拼成整齐的矩形。

**不算的情况**：图本身就是竖构图的信息图（如层级树），或期刊模板限定 `\columnwidth` 且图已撑满——如实报告"受模板限制"。

## 3. 流程图（pipeline / framework figure）

**构图占 70%，画法占 30%。** 组件画得再精致，构图不对就是不好看。

- **填满**：整图撑满栏宽（或版心宽），不留两侧白边。
- **比例 ≥ 4:3，长大于宽，"越长越好"**：横向长条最贴合双栏版面的矩形。
- **模块分区**：用虚线框或底色卡片按模块名（如 Encoder / Router / Decoder）分块，块与块之间用空白分隔、块内间距更小——让读者能把图的每一块对应到 Methods 的某一节。
- **空白均匀**：所有粒度（组件间、卡片间、卡片与画布边）的间距必须成比例，不能出现"这里挤、那里空"。

**不算的情况**：图里塞的是结果曲线（那是结果图，不是流程图）；或图必须保持正方形才能表达拓扑（有向环、网格）。

## 4. Sections & Subsections

| 问题 | 判据 | 修法方向 |
|---|---|---|
| 层级过深 | 出现 `\subsubsection`（即三级以下） | 改 `\paragraph{...}` 或改用列表 |
| 列表像凑篇幅 | 默认 `itemize`（左缩进 + 条目间距） | `enumitem` 紧凑化 |
| 行内代码体 | 正文出现 `\texttt{ModuleName()}` | 数学表达 / `\url` / `\path` |

**为什么**：`\subsubsection` 会在两个短标题之间拉出一段尴尬的空白；默认列表的左缩进让整栏右边界参差；`\texttt` 不参与断词，会把整行词距撑开。

**注意**：`\paragraph` 是行内小标题（后面直接接正文），视觉上最紧凑。列表要用就统一用，不要一段列表一段 `\paragraph` 混着来。

## 5. 表格

| 判据 | 阈值 | 说明 |
|---|---|---|
| 撑满栏宽 | ≥ 92% 栏宽（< 75% 为 P1） | 宁可加列内文字、调 `\tabcolsep`，也不要两侧各留 50pt 白 |
| 表内字号统一 | 全文所有表同一字号 | 比正文略小（`\small` 或 `\footnotesize`），但**必须一致** |
| 表头不单列过宽 | — | 数据集名另起一行，指标用 `\cmidrule` 框定 |
| 边距与图一致 | — | 表与图都要对齐页边距 |

**为什么**：表格是最容易被 reviewer 拿来判断"这作者细不细"的地方。一张表用 `\small`、另一张 `\footnotesize`，两张表并排时字号差异肉眼可见。

**不算的情况**：跨栏表（`table*`）本来就比栏宽，基准是版心宽；只有两三列的小表若强行撑满会显得空旷，这时应增加列内表述而不是加 `\tabcolsep`。

## 6. 公式

| 判据 | 判定 | 修法 |
|---|---|---|
| 右边界不越栏 | 越出 > 2pt 即问题 | 拆行 / 缩系数 / 换行内表达 |
| 编号不单独成行 | 编号 `(n)` 出现在公式下方或右下角独行 | 让公式整体宽度略小于栏宽，给编号留位 |
| 在算子处对齐 | 多行公式用 `align` + `&` 对齐 `=`、`+` | — |
| 不拆语义项 | 一个完整公式项（如 `\mathbb{E}_{x\sim p}[...]`）不得被断成两行 | 改在算子处断 |

**为什么**：编号掉行是最隐蔽的——看起来"没越界"，但读者要往下找编号。而把公式项拆两半比 hyphen 断词严重得多：hyphen 按音节断词，读者能拼回去；公式项是语义整体，断在中间直接读错。

**不算的情况**：`equation*`（无编号）不需要给编号留位；`align` 多行公式每一行都要各自检查右边界。

## 附：优先级定义

| 级别 | 含义 | 默认处理 |
|---|---|---|
| P0 | 一眼可见，破坏矩形轮廓（越界、编号掉行、lonely widow、< 50% 末行） | 必修 |
| P1 | 需要看第二眼（表宽 < 75%、段末 50–70%） | 建议修 |
| P2 | 细节一致性（字号不统一、图 70–92% 栏宽） | 视时间 |
| P3 | 风格偏好（`\texttt`、列表间距） | 可选 |
